3 Meet the ESP32

What is a microcontroller?

A microcontroller is a tiny computer that runs exactly one program, on repeat, forever. Think of it like a vending machine: you press a button (input), it runs a fixed set of instructions, and dispenses a drink (output). Unlike your laptop, a microcontroller doesn't run an operating system — it just runs your code, as fast as it can, until the power is cut.

The ESP32 DevKitC V4 is the microcontroller you'll use throughout all five WaveKit modules. Here's what's on it:

  • Dual-core processor at 240 MHz — fast enough to handle WiFi and motor control simultaneously
  • Built-in WiFi + Bluetooth — used in Modules 4 and 5 to control the boat from your phone
  • 30 GPIO pins — the metal pins around the edge you connect things to
  • Built-in blue LED on GPIO 2 — you'll blink this today, no wiring needed
What is GPIO?

General Purpose Input/Output. Each GPIO pin can be set to output mode (sends voltage — controls LEDs, motors) or input mode (reads voltage — detects buttons, sensors).

What's special about GPIO 2?

The DevKitC V4 has a tiny blue LED soldered directly to pin 2. When your code turns it on (sends voltage to it), the LED lights up — no wiring needed for this module.

5 One Line of Code

Code is a recipe — a list of instructions the ESP32 follows exactly, one at a time, in order. The language we use is called C++, and the files we write are called sketches (Arduino's word for a program, saved as .ino).

Before looking at a full program, let's zoom in on the smallest possible piece: one instruction.

// starts a comment — any text after // on the same line is a note for humans. The ESP32 completely ignores it. Comments explain what code does without affecting how it runs.

Each instruction ends with ; — like a full stop at the end of a sentence. It tells C++ "this instruction is finished." Forgetting one is one of the most common beginner mistakes — Arduino IDE will flag it as an error.

Anatomy of an instruction

C++ — one instruction
delay(1000);
① Name
delay

The name of the instruction — tells the ESP32 what to do. Arduino comes with many built-in instructions; you'll learn a handful today.

② Input
(1000)

The value passed in — inside the parentheses. delay needs to know how long to wait, so you give it a number in milliseconds. 1000 ms = 1 second.

③ Full stop
;

The semicolon ends the instruction. Every single instruction ends with one — no exceptions. Miss it and Arduino IDE will flag an error on that line.

Some instructions take two inputs

C++ — two inputs, separated by a comma
digitalWrite(2, HIGH);

Same pattern: name → ( inputs ) → ;. This time there are two inputs separated by a comma: the pin number (2) and the state (HIGH). HIGH and LOW are pre-built words that Arduino defines for you — written in ALL CAPS by convention to signal "this is a fixed, built-in value, not something you invented."

6 Naming Things

You just saw digitalWrite(2, HIGH);. The 2 is the GPIO pin number for the ESP32's built-in LED. But what if you used that pin number in ten different places? You'd type 2 every time — and if you ever switched to a different LED, you'd have to hunt down every single occurrence. Worse, bare numbers tell you nothing: 2 could mean anything.

The solution: give values a name.

C++ — giving a value a name
const int LED_PIN = 2;
const
constant

This value is set once and cannot change while the program runs. Marking it constant protects you from accidentally overwriting it later.

int
integer

The type of value stored — a whole number with no decimal point. Pin numbers are always whole numbers, so int is the right type.

LED_PIN
the name

The name you choose. All-caps with underscores is a convention for constants — it signals "this is a fixed label." You can name it anything, but a clear name makes code read like English.

= 2
the value

The number being stored — GPIO pin 2, the physical pin where the ESP32's built-in LED is wired (you saw this in section 3).

The payoff: readable code

Compare these two lines — they do exactly the same thing:

C++ — before and after naming
digitalWrite(2, HIGH);      // What is 2? You have to remember.
digitalWrite(LED_PIN, HIGH);  // Reads like English.

From now on the sketch uses LED_PIN everywhere. If you ever change pins, you update only the one line where LED_PIN is defined.

7 setup() and loop()

You know what one instruction looks like, and how to name values. The last piece before the full program: how do you group instructions together and tell the ESP32 when to run them?

Curly braces group instructions

Curly braces { } wrap a group of instructions that belong together. Everything between { and } is the body — the list of instructions that runs as a unit.

A function is a named group

When you give a group of instructions a name and a header line, it becomes a function:

C++ — what a function looks like
void functionName() {
  // instructions go here
}
void
no result handed back

Means "this function doesn't return a value when it's done — it runs its instructions and stops." Both setup() and loop() always start with void.

()
inputs (empty here)

The parentheses after the name are where you'd pass information in. For setup() and loop() nothing needs to be passed, so they're always left empty.

{ }
the body

Everything inside the curly braces is the function's body — the instructions it runs. Each instruction inside still ends with its own ;.

The two functions every sketch must have

Every single sketch — no matter how simple or complex — must contain exactly these two functions. They are not optional.

An everyday analogy

Think of setup() like your morning routine — things you do once when you wake up. Think of loop() like your daily work — it repeats over and over until you stop.

C++ — skeleton of every sketch
void setup() {
  // Runs ONCE on power-on
}

void loop() {
  // Runs FOREVER after setup()
}

8 Read the Blink Sketch

Here is the complete program. Read every line carefully — each one is explained below. Take your time; the next step will ask you to fill in parts of this sketch from memory.

C++ — blink.ino
// Blink built-in LED once per second

const int LED_PIN = 2;

void setup() {
  pinMode(LED_PIN, OUTPUT);
}

void loop() {
  digitalWrite(LED_PIN, HIGH);
  delay(1000);

  digitalWrite(LED_PIN, LOW);
  delay(1000);
}

What each line does

  1. const int LED_PIN = 2;
    const = constant (can't be changed), int = integer (whole number). Creates a named box called LED_PIN holding the number 2. That 2 is the GPIO pin number — the ESP32's built-in LED is physically wired to GPIO 2. Using a name means if you want a different pin, you change only this one line.
  2. void setup() { ... }
    void means "this function doesn't hand back a result." Everything inside the curly braces runs once, right when the board powers on. Use it for one-time setup tasks.
  3. pinMode(LED_PIN, OUTPUT);
    Tells the ESP32 "GPIO 2 will send voltage". Without this line, digitalWrite() has no effect.
  4. void loop() { ... }
    void again — no result handed back. Everything inside here repeats forever. When the closing } is reached, it jumps back to the top.
  5. digitalWrite(LED_PIN, HIGH);
    Sends 3.3V (the ESP32's full output voltage) through GPIO 2. The built-in LED lights up.
  6. delay(1000);
    Pauses 1000 milliseconds (= 1 second). The LED stays on during this pause.
  7. digitalWrite(LED_PIN, LOW);
    Sends 0V through GPIO 2. The LED turns off.
  8. delay(1000);
    Pauses another second, then loop() restarts from step 5.
About delay()

delay() freezes the entire chip while it waits. That's fine here, but later modules use a smarter approach so WiFi and motors can run at the same time.

11 Check Your Knowledge

Six questions — one per key part of the blink sketch. Pick the best answer for each. An explanation appears immediately after you choose so you understand why, not just what. You need all 6 correct to move on.

0 / 6 correct

Q1 — What name belongs in the blank?

const int ______ = 2;
LED_PIN is correct. Constant names are written in ALL_CAPS by convention — it signals "this value is fixed, not something that changes." LED_PIN also describes exactly what is stored: the GPIO pin number for the LED. 2 is the value, not the name. ledpin breaks the all-caps convention. pin is too vague.

Q2 — Which instruction configures a pin's direction?

void setup() {
  ______(LED_PIN, OUTPUT);
}
pinMode is correct — its name literally says what it does: it sets the mode of a pin (input or output). Without calling it first, digitalWrite() has no effect. digitalWrite sends a signal after the pin is configured. delay pauses the program. setup is the function we're already inside.

Q3 — Should the LED pin be set to INPUT or OUTPUT?

pinMode(LED_PIN, ______);
OUTPUT is correct. The ESP32 is sending voltage to the LED — the pin pushes current out. INPUT mode is used for reading sensors or buttons where voltage flows in. HIGH is a voltage level, not a pin mode. WRITE does not exist in Arduino.

Q4 — Which value turns the LED on?

digitalWrite(LED_PIN, ______); // turn LED on
HIGH is correct. It sends the ESP32's full 3.3V through the pin, which lights the LED. LOW sends 0V — the LED turns off. ON and 1 are not valid Arduino constants for digitalWrite().

Q5 — What number makes the LED stay on for exactly 1 second?

delay(______); // wait 1 second
1000 is correct. delay() counts in milliseconds — thousandths of a second. 1000 ms = exactly 1 second. 100 = 0.1 s (too short). 1 = 0.001 s (barely a blink). 10000 = 10 seconds (way too long).

Q6 — Which value turns the LED off?

digitalWrite(LED_PIN, ______); // turn LED off
LOW is correct. It sends 0V through the pin — no voltage, no current through the LED, so it goes off. HIGH would turn it on. OFF and 0 are not valid constants for digitalWrite().
Also type this into Arduino IDE

Open a new sketch in Arduino IDE (File → New Sketch). Arduino will give you an empty setup() and loop() — delete everything in the editor and type the complete code fresh. You'll need it ready for the Upload step.

10 Experiment: Change the Speed

Now that your code is running, let's modify it. Changing a running program and seeing the result is how all programmers work — every day, at every skill level.

Try it: make it blink faster

In Arduino IDE, change both delay(1000); lines to delay(200);. Click Upload again. The LED should now blink 5× faster.

Now try delay(50)

At 50ms the LED flickers so fast it looks dim — the human eye can't keep up. This effect is called PWM (Pulse Width Modulation — rapidly switching a pin on and off to fake a lower voltage level) and you'll use it deliberately in Module 2 to control the servo.

The core loop of all programming

Write → Upload → Observe → Modify. You've got the workflow down.

12 Challenge — SOS Blink

Morse Code SOS

Program the international distress signal using only digitalWrite() and delay().

· · ·   — — —   · · ·
  • S (short · ): 200ms on, 200ms off — repeat 3 times
  • O (long — ): 600ms on, 200ms off — repeat 3 times
  • Between full SOS cycles: 2000ms pause
Not sure how to start?

Write it in plain English first, then translate each line into code:
"Turn ON 200ms. Turn OFF 200ms. Repeat that 3×. Then ON 600ms, OFF 200ms, 3×. Then short pattern again. Then wait 2000ms."
Each "turn ON for Xms" = digitalWrite(LED_PIN, HIGH); delay(X);

Give it a genuine try before peeking at a solution.

C++ — sos.ino 
const int LED_PIN = 2;

void setup() {
  pinMode(LED_PIN, OUTPUT);
}

void loop() {
  // S — three short blinks
  digitalWrite(LED_PIN, HIGH); delay(200);
  digitalWrite(LED_PIN, LOW);  delay(200);
  digitalWrite(LED_PIN, HIGH); delay(200);
  digitalWrite(LED_PIN, LOW);  delay(200);
  digitalWrite(LED_PIN, HIGH); delay(200);
  digitalWrite(LED_PIN, LOW);  delay(200);
  // O — three long blinks
  digitalWrite(LED_PIN, HIGH); delay(600);
  digitalWrite(LED_PIN, LOW);  delay(200);
  digitalWrite(LED_PIN, HIGH); delay(600);
  digitalWrite(LED_PIN, LOW);  delay(200);
  digitalWrite(LED_PIN, HIGH); delay(600);
  digitalWrite(LED_PIN, LOW);  delay(200);
  // S again
  digitalWrite(LED_PIN, HIGH); delay(200);
  digitalWrite(LED_PIN, LOW);  delay(200);
  digitalWrite(LED_PIN, HIGH); delay(200);
  digitalWrite(LED_PIN, LOW);  delay(200);
  digitalWrite(LED_PIN, HIGH); delay(200);
  digitalWrite(LED_PIN, LOW);  delay(200);
  delay(2000);
}
