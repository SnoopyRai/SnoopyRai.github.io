3 What is a WebSocket?

In Module 4 you used HTTP — your phone sends a request, the ESP32 replies with HTML, and the connection closes. That works fine for loading a page, but it’s terrible for a boat controller.

Imagine pressing Forward on your phone. With HTTP, your phone would have to open a new connection, send a request, wait for a reply — for every single button tap. By the time the request arrives, you’ve already let go of the button.

The phone call analogy

HTTP is like sending a letter — you write it, post it, wait for a reply. WebSocket is like a phone call that stays open. Once connected, either side can speak at any moment, with no delay.

The phone loads the controller page over HTTP (port 80) just once. Then it opens a WebSocket on port 81 and the connection stays open. Every button press sends a single character — the ESP32 receives it instantly and moves the hardware.

4 The Command Protocol

When the phone sends a WebSocket message, the ESP32 has to know what it means. We keep it simple: one character per command. No JSON, no headers, no parsing — just a single letter.

CharacterMeaningHardware action
FForwardMotor → ledcWrite(0, 128)
SStop motorMotor → ledcWrite(0, 0)
LRudder leftServo → write(45)
RRudder rightServo → write(135)
CCentre rudderServo → write(90)
Why single characters?

The ESP32 receives these as raw bytes. A single ASCII character is 1 byte — there’s nothing smaller. It also makes the switch statement in C++ trivially simple: case 'F': no string comparison needed.

Button behaviour

The rudder and motor use press-and-hold semantics:

  • Left button pressed → send L
  • Left button released → send C (rudder centres automatically)
  • Forward button pressed → send F
  • Forward button released → send S (motor stops automatically)

This means you don’t need to separately tap “stop” — the boat does it the moment your thumb lifts off the screen.

Part 2 — Controller HTML page in PROGMEM

PROGMEM (Program Memory) tells the compiler to put this large string in the ESP32’s flash memory (4 MB) instead of RAM (320 KB). Without it, a long HTML string could use up all available RAM before your program even starts.

The R"rawliteral(...)rawliteral" syntax is a C++ raw string literal. Anything between the markers is treated as plain text — no need to escape quotes or angle brackets.

Part 3 — WebSocket event handler

This function is called automatically whenever a message arrives from the phone. The switch statement reads the first character of the message and calls the right servo or motor function.

C++ — WebSocket event handler
void onWsEvent(uint8_t num, WStype_t type,
                uint8_t* payload, size_t length) {
  if (type != WStype_TEXT || length < 1) return;
  char cmd = (char)payload[0];
  switch (cmd) {
    case 'L': rudder.write(45);                    break;
    case 'R': rudder.write(135);                   break;
    case 'C': rudder.write(90);                    break;
    case 'F': ledcWrite(0, 128);                   break;  // ~50% speed forward
    case 'S': ledcWrite(0, 0);                     break;  // stop
  }
}

Part 4 — setup() and loop()

C++ — setup() and loop()
void handleRoot() {
  httpServer.send_P(200, "text/html", CONTROLLER_HTML);
}

void setup() {
  Serial.begin(115200);

  // Set up LEDC for DC motor (from M3)
  ledcSetup(0, 1000, 8);            // channel 0, 1 kHz, 8-bit
  ledcAttachPin(MOTOR_PIN, 0);      // GPIO 26 → channel 0
  ledcWrite(0, 0);                  // start stopped

  // Centre rudder (from M2)
  rudder.attach(RUDDER_PIN);
  rudder.write(90);

  // Start WiFi access point (from M4)
  WiFi.softAP(SSID, PASSWORD);
  Serial.print("AP IP: ");
  Serial.println(WiFi.softAPIP());

  // Register HTTP route
  httpServer.on("/", handleRoot);
  httpServer.begin();

  // Start WebSocket server, register event handler
  wsServer.begin();
  wsServer.onEvent(onWsEvent);

  Serial.println("Ready! Connect to WaveKit WiFi then open 192.168.4.1");
}

void loop() {
  httpServer.handleClient();  // serve the page if requested
  wsServer.loop();             // process WebSocket messages
}
Two lines in loop() — that’s it

httpServer.handleClient() checks if the browser wants a new page load. wsServer.loop() checks if a button was pressed. Together they handle everything. The ESP32’s loop() runs thousands of times per second, so neither call is ever late.

9 Check Your Knowledge

Five questions about what you just read. Each must be correct before you can continue — wrong answers will highlight the right one so you can learn from them.

0 / 5 correct

Q1 — What key advantage does WebSocket have over HTTP for a boat controller?

Persistent connection is the key. HTTP opens and closes a new connection for every request — fine for loading a page, too slow for real-time control. WebSocket stays open once established, so sending a command is as instant as typing a character.

Q2 — What does PROGMEM do when applied to a large string?

Flash instead of RAM is correct. The ESP32 has 320 KB of RAM but 4 MB of flash. The controller HTML string is hundreds of bytes — too large to leave in RAM alongside your running program. PROGMEM pushes it to flash where there’s plenty of room.

Q3 — The Forward button uses onpointerdown="send('F')" and onpointerup="send('S')". What does the motor do when you lift your thumb?

Automatic stop on lift is the behaviour. onpointerup fires the moment the finger leaves the screen, sending 'S' which calls ledcWrite(0, 0). This prevents the boat from continuing to motor if you lose connection or let go.

Q4 — Why must wsServer.loop() be called inside void loop()?

Message polling is the answer. wsServer.loop() is a non-blocking poll — it checks the network buffer for any incoming messages. If one is there, it calls your onWsEvent function. Without this call in every iteration of loop(), button presses would stack up silently and be ignored.

Q5 — The controller page is loaded over HTTP. After that, button commands travel via ___.

WebSocket on port 81 is correct. The JavaScript in the controller page does new WebSocket('ws://' + location.hostname + ':81/') immediately on load. From that point, all button events go through the WebSocket at port 81 — the HTTP server at port 80 is idle until someone reloads the page.

Check MOTOR_PIN (26) is connected to the transistor Base via the 1 kΩ resistor. Confirm ledcSetup and ledcAttachPin run in setup(). Add Serial.println(cmd); inside onWsEvent to confirm 'F' messages are arriving.

8 Calibrate & Tune

The default values (write(45) for left, write(135) for right, ledcWrite(0, 128) for forward) are starting points. Your boat might need different values depending on how the servo horn is positioned and how fast the motor spins at 50% duty.

Tuning the rudder angles

In onWsEvent, find the three rudder lines and adjust the angles:

VariableDefaultIf boat steers too littleIf it steers too hard
Left angle45°Decrease (e.g. 30°)Increase (e.g. 60°)
Centre90°Usually fine as-isAdjust ±5° if boat pulls to one side
Right angle135°Increase (e.g. 150°)Decrease (e.g. 120°)

Tuning the motor speed

In onWsEvent, find case 'F' and change the duty cycle (0–255):

Duty valueApprox. speedUse for
0StoppedStop command
64~25%Very slow — indoor bench test
128~50%Default forward — good starting point
200~78%Moderate speed in water
255100%Full speed (test outdoors first)
Start low, work up

Test with ledcWrite(0, 64) first to confirm the motor spins, then increase the value gradually. Higher duty cycles generate more heat in the transistor — confirm the circuit stays cool before going above 200.
