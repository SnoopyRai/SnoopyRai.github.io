3 Meet the Motor

A DC motor spins when current flows through its internal coils, creating a magnetic field that pushes against permanent magnets inside the casing. Reverse the current → motor spins the other way. More current → more torque.

The problem: a 5 V DC motor can draw 200–600 mA when running. An ESP32 GPIO pin can only source about 40 mA. Connect the motor directly and you'll either get nothing, or damage the ESP32.

Solution: use a transistor as a switch

A transistor is an electronic switch. A tiny current at the Base (B) leg allows a much larger current to flow from Collector (C) to Emitter (E). The ESP32 GPIO sends the small signal; the transistor uses that to switch the motor's bigger current.

Base (B)
Control input

Connected to GPIO 26 via a 1 kΩ resistor. A small current here turns the switch on.

Collector (C)
High-current input

Connected to the motor's negative terminal. Motor current flows in here from 5 V.

Emitter (E)
Current exits

Connected to GND. Current flows out here, completing the motor's circuit through ground.

Flyback diode
Spike protection

Motors generate a reverse voltage spike when they stop. The 1N4001 diode across the motor absorbs this and protects the transistor.

PWM controls speed

By switching the transistor on and off very rapidly (using PWM), you vary how much average current reaches the motor — and that controls its speed. Full on = full speed; 50% duty cycle = roughly half speed.

4 LEDC PWM

The ESP32 has a hardware peripheral called LEDC (LED Control) that generates PWM signals on any GPIO. You set three things: a channel (0–15), a frequency in Hz, and a resolution in bits. Then you call ledcWrite() with a duty-cycle value to set speed.

Why 8-bit?

8 bits gives you 28 = 256 steps (0–255). That's plenty of speed resolution for a motor. The frequency (1000 Hz) means the transistor switches 1000 times per second — fast enough that the motor sees smooth average power, not individual pulses.

No library to install

LEDC is built directly into the ESP32 Arduino core. You don't need #include — just call ledcSetup(), ledcAttachPin(), and ledcWrite() directly.

7 The Motor Sketch

Here's the full sketch. Read through every line — each one is explained in the comments. No libraries to install; LEDC is built into the ESP32 Arduino core.

C++ — WaveKit M3 Motor Sketch 
// WaveKit M3 — DC Motor Speed Control
// Uses the ESP32's built-in LEDC peripheral — no library needed

const int MOTOR_PIN = 26;  // Signal wire → GPIO 26 → resistor → transistor Base

void setup() {
  // Configure LEDC channel 0: 1 kHz frequency, 8-bit resolution (0–255)
  ledcSetup(0, 1000, 8);

  // Connect GPIO 26 to channel 0
  ledcAttachPin(MOTOR_PIN, 0);

  // Start with motor stopped (duty cycle = 0)
  ledcWrite(0, 0);
}

void loop() {
  ledcWrite(0, 128);   // 50% speed — motor spins for 3 seconds
  delay(3000);

  ledcWrite(0, 0);     // Stop — pause for 2 seconds
  delay(2000);
}

Key functions at a glance

ledcSetup()
ledcSetup(0, 1000, 8)

Channel 0, 1 kHz, 8-bit. Duty range = 0 (off) to 255 (full).

ledcAttachPin()
ledcAttachPin(26, 0)

Binds GPIO 26 to channel 0 — now ledcWrite controls that pin.

Half speed
ledcWrite(0, 128)

128 / 255 ≈ 50% duty cycle — a safe first-test speed.

Stop
ledcWrite(0, 0)

Duty cycle = 0 → transistor fully off → motor gets no current.

No library, no arming

Unlike the servo from Module 2, LEDC doesn't need #include — it's part of the ESP32 core. And unlike an ESC, a transistor needs no arming sequence. Just set the duty cycle and go.

9 Check Your Knowledge

Five questions about DC motors and LEDC PWM. You need all five correct to continue — wrong answers highlight the right one so you can learn from them.

0 / 5 correct

Q1 — Why can't you connect a 5V DC motor directly to a GPIO pin?

Current limit is the reason. A GPIO pin is designed to control small signals — not power loads. Connecting a motor directly risks either getting no movement (not enough current) or permanently damaging the ESP32. That's why we use a transistor: it's a current amplifier that uses the tiny GPIO signal to switch a much larger motor current.

Q2 — In this line, what does the 8 represent?

ledcSetup(0, 1000, 8);
Bit resolution is correct. 8 bits means 28 = 256 steps, so the duty cycle runs from 0 (fully off) to 255 (fully on). The three arguments in order are: channel (0), frequency in Hz (1000), and resolution in bits (8). Each controls something different.

Q3 — Which transistor leg connects to the GPIO pin (via the 1 kΩ resistor)?

Base (B) is the control input. A tiny current into the Base turns the transistor "on," letting large current flow from Collector to Emitter. The 1 kΩ resistor limits the GPIO current to a safe level before it reaches the Base. Collector connects to the motor's negative terminal; Emitter connects to GND.

Q4 — What speed does ledcWrite(0, 128) give the motor?

ledcWrite(0, 128);
~50% speed is correct. With 8-bit resolution, the full range is 0–255. 128 ÷ 255 ≈ 50%. At this duty cycle the transistor switches on and off 1000 times per second, with the pulse "on" for exactly half of each cycle — giving the motor roughly half its maximum power.

Q5 — What is the flyback diode (1N4001) for in this circuit?

Flyback protection is correct. When the motor suddenly stops, its spinning coils act like a generator and push a brief reverse voltage spike back into the circuit. Without the diode, this spike can destroy the transistor or the ESP32. The 1N4001 is placed across the motor terminals (cathode to +) to provide a safe path for that reverse current to dissipate harmlessly.

⚠ Motor doesn’t spin at all?

Check GPIO 26 is connected to the Base via the 1 kΩ resistor (not directly). Confirm motor (+) is on 5V and Emitter is on GND. Make sure ledcAttachPin(MOTOR_PIN, 0) runs in setup().

⚠ Motor runs but won’t stop?

Make sure ledcWrite(0, 0) is correctly calling channel 0 (same channel used in ledcSetup and ledcAttachPin). If the channels don't match, the write has no effect.

⚠ Motor gets warm or smells? Circuit feels hot?

Stop immediately. Check for a short circuit — motor terminals touching, or Collector and Emitter legs swapped. The 1N4001 diode must be across the motor terminals (not the transistor).

⚠ Upload fails with “Connecting…”?

Hold BOOT while clicking Upload; release when dots appear in the console.

10 Challenge — Smooth Speed Ramp

Right now the motor jumps from 0 to 128 instantly. Can you make the speed ramp up and back down gradually? Use a for loop to step through duty-cycle values one increment at a time.

The goal

Replace the ledcWrite(0, 128) jump in loop() with two for loops — one ramping up (0 → 200) and one ramping down (200 → 0). Each step adds a small delay() to spread the ramp smoothly over time.

Have a go at writing the loops yourself before revealing the hint:

C++ — hint: smooth speed ramp in loop() 
// Replace the contents of loop() with these two ramps:

// Ramp UP: duty 0 → 200 (~78% speed)
for (int speed = 0; speed <= 200; speed += 5) {
  ledcWrite(0, speed);
  delay(50);   // try 20 for a faster ramp, 100 for slower
}
delay(2000);    // hold at speed 200 for 2 seconds

// Ramp DOWN: duty 200 → 0
for (int speed = 200; speed >= 0; speed -= 5) {
  ledcWrite(0, speed);
  delay(50);
}
delay(2000);    // pause at stop before repeating
Try tweaking the step size

Change += 5 to += 10 for a faster ramp, or += 2 for an ultra-smooth one. Raise the top speed from 200 to 255 for full power — but test at a lower value first and confirm the motor and circuit stay cool.
