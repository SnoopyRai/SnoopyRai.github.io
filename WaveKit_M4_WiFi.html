3 Station vs. Access Point

Every WiFi device operates in one of two roles:

Station (STA)
WiFi.begin(ssid, pass)

Joins an existing network. Your laptop and phone usually run in this mode — they connect to a router.

Access Point (AP) ← we use this
WiFi.softAP(ssid, pass)

Creates its own network. The ESP32 becomes the router — other devices connect directly to it.

As an Access Point, the ESP32 doesn't need internet. It just needs to be powered. Any phone within WiFi range can connect to it directly — perfect for controlling a boat on a lake where there's no router.

TermWhat it means
SSIDThe WiFi network name (what you see in the WiFi list)
PasswordThe key to join the network (minimum 8 characters)
IP addressThe ESP32's "address" on the network — always 192.168.4.1 in AP mode
Port 80The standard port for HTTP web pages (your browser assumes port 80 automatically)

4 What is a Web Server?

When your phone connects to the WaveKit WiFi, it has a channel to the ESP32 — but no web pages yet. To send a page, the ESP32 needs to run a web server.

A web server is a program that listens for browser requests and sends back HTML. Every website you've ever visited — Google, YouTube, any page — is delivered by a web server. Ours just happens to run on a chip the size of a matchbox.

The request–response conversation

📱
Your phone
(browser / client)
GET / HTTP/1.1 →
← 200 OK · text/html · <html>...</html>
🔌
ESP32
(web server)

This exchange happens in milliseconds. In our sketch, the WebServer library handles all the HTTP formatting — you just write what to send back.

Status 200
200 OK

Request succeeded — here's the page

Status 404
404 Not Found

The server couldn't find that path

Content type
"text/html"

Tells the browser to render the response as a web page

Route handler
server.on("/", fn)

"When someone requests '/', call this function"

5 HTML in a C++ String

The web page the ESP32 serves is just a text string containing HTML. Here's the minimal structure:

HTML — the page we'll serve 
<!-- Every web page starts with this -->
<!DOCTYPE html>
<html>

<head>
  <!-- Title shown in the browser tab -->
  <title>WaveKit</title>
  <!-- Makes it look correct on a phone screen -->
  <meta name='viewport' content='width=device-width,initial-scale=1'>
</head>

<body>
  <h1>Hello from WaveKit!</h1>   <!-- Big heading -->
  <p>Your ESP32 is serving this page.</p>  <!-- Paragraph -->
</body>

</html>

In C++, this becomes a string passed directly to server.send(). String literals next to each other are joined automatically, which keeps long HTML readable:

C++ — HTML as a string 
server.send(200, "text/html",
  "<!DOCTYPE html><html>"
  "<head><title>WaveKit</title></head>"
  "<body><h1>Hello from WaveKit!</h1></body>"
  "</html>"
);
You don't need to know HTML

6 The Access Point Sketch

Here's the full sketch. Read every comment — it maps directly to what you learned in the last two sections.

C++ — WaveKit M4 Access Point Sketch 
// WaveKit M4 — WiFi Access Point + Web Server

#include <WiFi.h>       // Built into the ESP32 board package
#include <WebServer.h>  // Also built in — no extra install needed

const char* SSID     = "WaveKit";      // WiFi network name
const char* PASSWORD = "wavekit123";   // Must be 8+ characters

WebServer server(80);  // Port 80 = standard HTTP

// Called when a browser requests the root path "/"
void handleRoot() {
  server.send(200, "text/html",
    "<!DOCTYPE html><html>"
    "<head><title>WaveKit</title>"
    "<meta name='viewport' content='width=device-width,initial-scale=1'></head>"
    "<body style='font-family:sans-serif;text-align:center;padding:40px;background:#EEF2FF'>"
    "<h1>Hello from WaveKit!</h1>"
    "<p>Your ESP32 is serving this page over WiFi.</p>"
    "</body></html>"
  );
}

void setup() {
  Serial.begin(115200);

  // Start the Access Point
  WiFi.softAP(SSID, PASSWORD);

  // Print the IP address to Serial Monitor
  Serial.print("WiFi network: ");
  Serial.println(SSID);
  Serial.print("Then open: http://");
  Serial.println(WiFi.softAPIP());  // Always 192.168.4.1

  server.on("/", handleRoot);  // Register the "/" route
  server.begin();               // Start listening
}

void loop() {
  server.handleClient();  // Check for and respond to browser requests
}

Key functions

Start the AP
WiFi.softAP(ssid, pass)

Creates the WiFi network. Devices can connect immediately after this line runs.

Get the IP
WiFi.softAPIP()

Returns the ESP32's IP address on its own network — always 192.168.4.1 by default.

Register a route
server.on("/", fn)

"When someone requests this path, call this function." Add more server.on() lines for extra pages.

Handle requests
server.handleClient()

Must be called in loop(). Without it, the server never processes any requests.

7 The Serial Monitor

The Serial Monitor is a text window in Arduino IDE that shows messages printed by your sketch. We use it to see the ESP32's IP address after upload.

How to open it

  1. Upload the sketch first (click →)
  2. Go to Tools → Serial Monitor (or press Ctrl + Shift + M / Cmd + Shift + M)
  3. Set the baud rate dropdown to 115200 — must match Serial.begin(115200) in the sketch
  4. Press the EN (Enable/Reset) button on the ESP32 to restart it and replay the startup messages

What you'll see

WiFi network: WaveKit
Then open: http://192.168.4.1

9 Check Your Knowledge

Five questions about WiFi, servers, and HTTP. All five correct to continue.

0 / 5 correct

Q1 — What does WiFi.softAP("WaveKit", "wavekit123") do?

Creates a new WiFi network called "WaveKit" is correct. softAP = software Access Point. Instead of joining an existing network, the ESP32 creates one. Any device within range can connect to "WaveKit" directly — no router, no internet needed. Perfect for controlling a boat on a lake.

Q2 — What port does WebServer server(80) listen on?

WebServer server(80);
Port 80 is correct. Port 80 is the default HTTP port. When you type http://192.168.4.1 in a browser, the browser automatically tries port 80. If you used a different port (like 8080), you'd have to type http://192.168.4.1:8080 explicitly.

Q3 — What does HTTP status code 200 mean?

server.send(200, "text/html", html);
OK — request succeeded is correct. 200 is "200 OK" — the most common HTTP response, meaning the server understood the request and is sending back the content. You might know "404 Not Found" from web browsing — that's what happens when the server can't find the page you asked for. Both are standard HTTP status codes.

Q4 — Why does server.handleClient() need to be called in loop()?

void loop() { server.handleClient(); // ← why? }
To check for and respond to incoming browser requests is correct. Each call to handleClient() asks: "has any browser sent an HTTP request?" If yes, it calls the matching handler — like handleRoot(). Without it in loop(), the server sets up but never responds to anything. The page would just time out in the browser.

Q5 — What is 192.168.4.1?

The ESP32's IP address on its own AP network is correct. When the ESP32 creates a softAP, it automatically assigns itself the IP address 192.168.4.1 — this is the default and never changes. Any phone connected to "WaveKit" WiFi can reach the ESP32 by opening http://192.168.4.1.

⚠ "WaveKit" doesn’t appear in phone's WiFi list?

Make sure the sketch uploaded successfully. Open Serial Monitor — if you see the IP address, the AP is running. Try moving your phone closer to the ESP32.

⚠ Browser shows "Site can’t be reached"?

Make sure your phone is connected to "WaveKit" (not your home WiFi). Check the URL starts with http:// not https://.

⚠ Serial Monitor shows garbage characters?

Set the baud rate to 115200 in the dropdown — it must match Serial.begin(115200) in the sketch.

⚠ Upload fails with "Connecting…"?

Hold BOOT while clicking Upload; release when dots appear in the console. Same fix as earlier modules.
