3 Meet the Servo

A servo motor is a motor + gearbox + position sensor all in one small package. Instead of just spinning, it moves to an exact angle and holds there. That's what makes it perfect for steering a rudder.

The SG90 is the servo in your WaveKit. It weighs 9 grams and can rotate between 0° and 180°.

4 What's a Library?

A library is extra code that someone else has already written — and that you can use in your own program by including it. Think of it like borrowing a tool from a toolbox instead of building it yourself.

To use the Servo library, you put this line at the very top of your sketch:

C++ 
#include <Servo.h>

This tells Arduino IDE: "Load the Servo library so I can use its functions."

Without the library
~50 lines of complex timer code

You'd have to write your own PWM signal from scratch. Very hard.

With the library
rudder.write(90)

One function call. The library handles everything for you.

Creating a Servo object

After including the library, you create a Servo object — a named variable that represents your physical servo motor:

C++ 
Servo rudder;   // creates a Servo object called "rudder"

You can name it anything — rudder makes sense because that's what it controls. Then in setup() you tell it which GPIO pin the signal wire is connected to:

C++ 
rudder.attach(13);   // signal wire is on GPIO 13

5 What is PWM?

PWM stands for Pulse Width Modulation. Instead of sending a constant voltage to the servo, the ESP32 sends a very fast repeating ON/OFF signal.

The servo reads how long the signal stays ON each cycle — that's called the pulse width. Different pulse widths = different angles:

0° left
1 ms
0°
Centre
1.5 ms
90°
180° right
2 ms
180°
You don't need to think about this

The Servo library converts your angle (0–180) into the right PWM pulse automatically. When you write rudder.write(90), the library sends a 1.5 ms pulse — you never have to touch the timing yourself.

This is why libraries are so useful — they hide the complicated details so you can focus on the interesting part: making the servo move.

Use the 5V pin, not 3.3V

If you power the servo from the 3.3V pin, it may twitch but not reach its full position. The ESP32's 3.3V output doesn't provide enough current for the servo's motor under load. Always use the 5V / VIN pin for servos.

Tick each wire as you connect it. The Done button unlocks only when all three are connected.

7 The Sweep Sketch

Open Arduino IDE, create a new sketch, and type or paste this code:

C++ — servo_sweep.ino 
// WaveKit M2 — Sweep the rudder servo left and right

#include <Servo.h>              // load the Servo library

Servo rudder;                 // create a Servo object named "rudder"

const int SERVO_PIN = 13;    // GPIO 13 — servo signal wire (orange)

void setup() {
  rudder.attach(SERVO_PIN);  // tell the library which pin to use
  rudder.write(90);          // centre the rudder on startup
  delay(500);
}

void loop() {
  rudder.write(0);           // full left
  delay(1000);

  rudder.write(90);          // centre
  delay(500);

  rudder.write(180);         // full right
  delay(1000);

  rudder.write(90);          // centre
  delay(500);
}

What each part does

Include
#include <Servo.h>

Loads the library. Must be at the very top, before anything else.

Object
Servo rudder;

Creates a variable that represents the physical servo. Goes before setup().

Attach
rudder.attach(SERVO_PIN)

Links the object to a GPIO pin. Call once in setup().

Move
rudder.write(angle)

Sets the angle (0–180). Call as many times as you like in loop().

Q1 — What does PWM stand for?

Pulse Width Modulation is correct. The ESP32 sends a repeating ON/OFF signal and the servo reads how long the pulse stays ON (the pulse width) to determine its angle. The Servo library handles all of this automatically when you call rudder.write(angle).

Q2 — Looking at the PWM diagram, what pulse width corresponds to the centre position (90°)?

0°: 1 ms pulse  |  90°: ? ms pulse  |  180°: 2 ms pulse
1.5 ms is correct — it's exactly halfway between 1 ms (0°) and 2 ms (180°), which gives the 90° centre position. You don't need to memorise these numbers — the Servo library converts angles to pulses automatically — but understanding the pattern helps you reason about what's happening.

Q3 — Which wire on the SG90 servo carries the PWM signal?

Red wire → 5V  |  Brown/Black wire → GND  |  ? wire → GPIO 13
Orange / Yellow is correct. The red wire is power, brown/black is ground, and orange/yellow is the signal. Swapping power and ground won't damage the servo but it won't work — and connecting the signal wire to the wrong pin just means your code controls nothing.

Q4 — What does the number 13 refer to in this line?

rudder.attach(13);
The GPIO pin number is correct. attach(pin) tells the Servo library which physical pin on the ESP32 the signal wire is connected to. In this sketch it's GPIO 13 — matching the orange wire in the wiring step. If you moved the wire to a different pin, you'd update this number too.

Q5 — What does this line do?

rudder.write(0);
Moves the servo to 0° (full left) is correct. write(angle) sends the servo to that specific angle. 0° is the leftmost position, 90° is centre, 180° is full right. It doesn't turn the servo off — to stop sending PWM you'd call rudder.detach().

⚠ Servo doesn’t move at all?

Check the orange/yellow signal wire is connected to GPIO 13. Confirm rudder.attach(SERVO_PIN) is inside setup(), not loop().

⚠ Servo twitches but won’t reach position?

Power issue — move the red wire from 3.3V to the 5V / VIN pin on the ESP32.

⚠ Compile error: ‘Servo’ was not declared?

Make sure #include <Servo.h> is at the very top of your sketch — it must be the first line.

⚠ Upload fails with “Connecting…”?

Hold the BOOT button while clicking Upload; release when dots appear in the console.

10 Challenge — Smooth Sweep

Right now the servo jumps between positions. Can you make it move smoothly instead? Use a for loop to step through angles one degree at a time.

The goal

Replace rudder.write(0) and rudder.write(180) jumps with two for loops — one counting up (0 → 180) and one counting down (180 → 0). Each step adds a small delay() to control the speed.

Have a go at writing the loop yourself before revealing the hint:

C++ — hint: smooth sweep in loop() 
// Replace the jump positions with these two loops:

// Sweep smoothly from 0° to 180°
for (int angle = 0; angle <= 180; angle++) {
  rudder.write(angle);
  delay(15);        // try 5 for fast, 30 for slow
}

// Sweep smoothly from 180° back to 0°
for (int angle = 180; angle >= 0; angle--) {
  rudder.write(angle);
  delay(15);
}
Try tweaking the delay

Change delay(15) to a smaller number for faster sweeping or a larger number for slower. At delay(5) the boat's rudder moves almost as fast as a real RC boat.
